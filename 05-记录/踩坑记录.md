## 2026-08-11

- 日期：2026-08-11
- 问题描述：Java 编译报「非法字符: '\ufeff'」
- 报错 / 现象：maven-compiler 编译失败，`EnterpriseAgentApplication.java:[1,1] 非法字符: '\ufeff'`
- 排查过程：PowerShell `Set-Content -Encoding UTF8`（Windows PowerShell 5.1）会写入 UTF-8 BOM，Java 源码不接受
- 解决方案：用 `[System.IO.File]::WriteAllText(path, content, (New-Object System.Text.UTF8Encoding($false)))` 写无 BOM UTF-8
- 涉及技术：PowerShell / Java / Maven

## 2026-08-12

- 日期：2026-08-12
- 问题描述：LangChain4j 1.18 编译报「找不到符号 generate(List<ChatMessage>)」
- 报错 / 现象：`ChatService.java:[32,49] 找不到符号 方法 generate(java.util.List<ChatMessage>)`
- 排查过程：LangChain4j 1.x 重构了模型 API，旧 0.x 的 `ChatLanguageModel.generate()` 已移除，改用 `ChatModel.chat()`；用 `javap` 查看了 1.18.1 的 `ChatModel` / `ChatResponse` / `OpenAiChatModelBuilder` 方法签名确认
- 解决方案：`ChatResponse response = chatModel.chat(chatMessages); String reply = response.aiMessage().text();`；测试用 `ChatResponse.builder().aiMessage(new AiMessage("...")).build()` 构造 mock 返回值
- 涉及技术：LangChain4j 1.x / Java

## 2026-08-13
- 日期：2026-08-13
- 问题描述：SSE 流式输出中文乱码
- 报错 / 现象：/chat/stream 返回的 data: 内容中文变成 â?¤ 等乱码；MockMvc 断言失败
- 排查过程：SseEmitter 响应默认按 ISO-8859-1 编码字符串，中文（UTF-8 字节）被当 Latin-1 解码
- 解决方案：控制器里显式 response.setCharacterEncoding("UTF-8")，并用 produces="text/event-stream;charset=UTF-8"
- 涉及技术：Spring MVC / SseEmitter / SSE / 编码

- 日期：2026-08-14
- 问题描述：DeepSeek 不支持 LangChain4j 的 json_schema 原生结构化输出
- 报错 / 现象：请求带 response_format.type=json_schema 时返回 {"error":{"message":"This response_format type is unavailable now","type":"invalid_request_error"}}
- 排查过程：先用 mock 单测通过，真实联调暴露；确认是模型服务端不支持该 response_format 类型
- 解决方案：默认改用 json_object 模式（ResponseFormat.JSON）+ system prompt 写明 JSON 结构 + 服务端 Jackson 解析并校验必填字段；保留 json_schema 模式供 OpenAI 系模型使用
- 涉及技术：LangChain4j / DeepSeek / JSON Schema
