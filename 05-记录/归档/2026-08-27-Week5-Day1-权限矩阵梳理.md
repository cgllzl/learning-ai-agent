# Week 5 Day 1 归档：梳理 Tool 权限矩阵（2026-08-27）

> 学习计划：`01-每周学习/Week-05-企业级Agent安全/学习目标.md` ｜ 笔记：`02-知识库/Agent安全/Day1-权限矩阵梳理.md`

## 今天做了什么

1. 梳理了项目里所有 Tool，形成权限矩阵（工具、所属模块、风险等级、允许角色、是否需人工审批）。
2. 把权限矩阵落成 Java 静态清单：`ToolRiskLevel` + `ToolPermission` + `ToolPermissionCatalog`。
3. 用真实 DeepSeek 演示：当前 Agent 没有任何权限校验，既能查订单，也能改订单状态。

## 权限矩阵要点

- `updateOrderStatus`：会改数据，需 ORDER_ADMIN / SUPERVISOR，且必须人工审批。
- `handleOrder`：内部可转达改状态，同样按会改数据处理。
- `getUser` / `getOrder`：敏感读取，涉及个人信息，需限制角色。
- MCP 的 `getOrder`：面向 EXTERNAL_AGENT，和内部工具分属不同暴露面。

## 验证

- `ToolPermissionCatalogTest`：4 个单测通过（清单完整、改状态需审批、getOrder 只读、能找出所有会改数据的工具）。
- `ToolPermissionLiveTest`：真实 DeepSeek 联调通过，模型成功读取 O1001 并把 O1003 改为 SHIPPED，验证「未加固前可改数据」。
