## 今天做了什么

1. **新增 `POST /chat/structured`（结构化输出）**
   - 入参：systemPrompt + messages + `schema`（extract 信息抽取 / ticket 工单分类）+ `mode`（json_object / json_schema）
   - 响应：`{"result": { ... }}` 结构化 JSON，服务端解析并校验必填字段
2. **`StructuredChatService`**：用 LangChain4j `JsonSchema` / `JsonObjectSchema` 等构建 schema，`ChatRequest.responseFormat` 指定输出格式
3. **双模式设计**：默认 `json_object`（DeepSeek 兼容）+ `json_schema`（OpenAI 原生严格模式）
4. **重构**：抽取共享的 `Messages` 工具类，三个 Service 共用消息转换逻辑
5. **测试全部通过（25 个）**：ChatControllerTest 9、ChatServiceTest 3、StreamingChatServiceTest 3、StructuredChatServiceTest 7、启动测试 1（另 2 个联调测试默认跳过）
6. **真实 DeepSeek 联调通过**：`StructuredChatServiceLiveTest` 用中文输入实测抽取 summary/keywords/sentiment 成功

## 接口示例

```http
POST /chat/structured
Content-Type: application/json

{
  "systemPrompt": "你是信息抽取助手，从用户输入中抽取信息。",
  "messages": [ { "role": "user", "content": "这个产品很好用，就是价格有点贵……" } ],
  "schema": "extract",
  "mode": "json_object"
}
```

```json
{ "result": { "summary": "产品整体满意，价格偏贵", "keywords": ["客服","价格"], "sentiment": "positive" } }
```

## 关键点与踩坑

- 结构化输出的价值：模型返回可被程序直接消费的 JSON。
- **DeepSeek 不支持原生 `json_schema` response_format**（报 `This response_format type is unavailable now`），只能用 `json_object` + prompt 强化 + 服务端校验（详见 `05-记录/踩坑记录.md`）。
- LangChain4j 按请求指定 `ResponseFormat`，不改模型 Bean。
