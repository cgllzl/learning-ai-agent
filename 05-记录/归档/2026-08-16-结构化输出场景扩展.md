# 2026-08-16 归档：结构化输出场景扩展

> 关联：Day 4 结构化输出 ｜ 代码：`04-项目/enterprise-agent` ｜ 笔记：`02-知识库/LLM应用开发/JSON-Schema结构化输出.md`

## 做了什么

1. **代码新增 3 个场景 schema**（`StructuredChatService`）：
   - `classify` 内容分类打标：`{category, tags[], confidence}`
   - `resume` 简历解析：`{name, years, skills[], education[]}`
   - `product` 商品属性抽取：`{name, category, price, stock_status}`
   - 加上已有的 `extract`、`ticket`，共 5 个内置场景，仍走同一套「schema 解析 → prompt 强化 → ResponseFormat → 解析 → 字段校验」链路
2. **测试**：单测新增 5 个场景用例（共 10 个），真实 DeepSeek 联调新增 classify/resume 两个场景（共 3 个），全部通过
3. **知识库**：`JSON-Schema结构化输出.md` 新增「七、典型使用场景」章节——为什么按 schema 入参构建、场景表、设计要点（接口复用/输出即契约/约束幻觉/生产注意 schema 白名单）

## 为什么这么做

- 一个接口服务多种业务结构，新增结构只加一个 schema 定义，核心链路不改。
- 演示「结构化输出」在真实场景里的价值：信息抽取、工单、分类打标、简历/商品解析、多业务线复用、以及预告 Week 2 的工具参数约束。

## 验证结果

- `mvn test`：30 个测试（26 个执行 + 4 个联调默认跳过）
- 真实 DeepSeek 联调（`StructuredChatServiceLiveTest`）：3 个场景（extract/classify/resume）全部通过
