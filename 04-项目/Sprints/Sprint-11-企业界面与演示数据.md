# Sprint 11：企业产品界面与演示数据

> 这是贯穿第二阶段优先级 1～3 的产品化 Sprint，不等到后端全部完成后才开始。

## 目标

把现有 Agent 能力做成可操作、可演示、可压测的企业产品，并形成可放进简历的证据。

## 前端任务

- [ ] React + TypeScript + Vite 工程、响应式后台布局、统一 API/SSE Client。
- [ ] 登录与演示身份、运营总览、AI 工作台。
- [ ] 订单中心、知识库中心、审批中心。
- [ ] Trace/审计、Evaluation、MCP/Skill 治理页面。
- [ ] 加载、空数据、失败、重试、权限不足和审批过期状态完整。
- [ ] 核心页面有组件测试和端到端测试。

## 数据任务

- [ ] 定义租户、用户、订单、物流、工单、审批、文档、Agent Run、审计和评估数据关系。
- [ ] 实现固定随机种子的 smoke/demo/load 数据生成器。
- [ ] smoke：500 订单；demo：50,000 订单；load：500,000 订单与 1,000,000 审计事件。
- [ ] 金额、时间、状态机、退款、审批和租户关系符合业务不变量。
- [ ] 数据可一条命令生成、清理并重建，不包含真实个人信息。

## 展示与简历任务

- [ ] 三条稳定演示链：带引用知识问答、订单查询、高风险审批。
- [ ] 系统架构图、Agent 调用链图、权限审批图。
- [ ] 页面截图和3～5分钟演示脚本或视频。
- [ ] 数据规模、P95、成功率、成本和安全结果有版本化报告。
- [ ] 中英文项目介绍与简历项目描述只引用实测数字。

## 完成标准

- [ ] 新用户按 README 能启动系统、生成 demo 数据并完成三条演示链。
- [ ] 多租户/RBAC 在页面和 API 两层表现一致。
- [ ] 大数据分页、检索、Trace 和看板在 load 档下有可核验结果。
- [ ] 项目达到面试现场可演示、追问时能讲清取舍和故障处理的程度。
