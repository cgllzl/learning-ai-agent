# 优先级 2：持久化、企业知识库与规模数据

> 状态：待开始。建议 6 个学习日；依赖优先级 1 主链路。对应 Sprint 3/4/6/11。

## 为什么接着学

第一优先级让车能跑起来。现在要解决“熄火再启动，行程和资料还在不在”：当前 Agent Run/Memory 和向量检索有学习期内存实现，无法凭一次进程内测试证明生产可靠。

## 六个学习日

| 日 | 学习任务与企业例子 | 离线验证 | 真实模型验证 |
| --- | --- | --- | --- |
| 1 | 定义 PostgreSQL 数据模型和迁移：租户/用户/订单/物流/售后/审批/审计/Agent 状态 | 约束、索引、状态机和跨租户 Repository 测试 | DeepSeek 规划订单任务并写入持久化 Run |
| 2 | 编写固定随机种子数据生成器，支持 smoke/demo/load；保证时间、金额、状态和外键关系合理 | 相同种子结果一致、业务不变量测试 | 使用 demo 数据完成真实订单查询 |
| 3 | 将 Checkpoint/幂等状态放入 PostgreSQL/Redis，模拟进程重启后恢复“已改订单、待通知” | 重启恢复、重复请求零额外副作用 | DeepSeek 触发任务，重启后继续并核对结果 |
| 4 | 将长期 Memory 持久化并加入 TTL/删除；避免不同租户共享对话 | 重启后同租户可读、异租户不可读、过期删除 | 两轮 DeepSeek 对话跨重启验证 |
| 5 | 将 RAG 接到 pgvector，文档原件放对象存储；实现租户/部门/级别过滤、更新、删除和重建 | 无权限文档召回为零、删除后不可检索 | DeepSeek 对同题按不同租户给出不同授权引用 |
| 6 | 生成 load 档数据，验证订单分页、审计查询、向量检索和前端大列表体验，记录索引与查询计划 | 50万订单/100万审计目标下的正确性与性能测试 | 从大量数据中完成一次真实订单和知识查询 |

## 完成标准

- [ ] 服务重启后可安全继续 Agent Run；重复请求不会重复业务副作用。
- [ ] Memory 有用户/租户隔离、保留期、删除策略。
- [ ] 向量检索在模型看到片段之前就完成文档级授权过滤。
- [ ] 关键数据可备份、迁移与重建，测试使用容器或可复现环境。
- [ ] 数据生成器支持 smoke/demo/load 和固定种子，任何演示数据都可重建。
- [ ] load 档达到目标规模后，分页、检索与租户过滤仍正确，实际性能记录到报告。

持久化让任务能继续，下一步还要知道它为什么慢、为什么失败、花了多少钱，因此进入优先级 3。
