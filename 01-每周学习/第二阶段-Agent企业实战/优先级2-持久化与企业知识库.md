# 优先级 2：持久化与企业知识库

> 状态：待开始。建议 4 个学习日；依赖优先级 1 主链路。对应 Sprint 3/4/6。

## 为什么接着学

第一优先级让车能跑起来。现在要解决“熄火再启动，行程和资料还在不在”：当前 Agent Run/Memory 和向量检索有学习期内存实现，无法凭一次进程内测试证明生产可靠。

## 四个学习日

| 日 | 学习任务与企业例子 | 离线验证 | 真实模型验证 |
| --- | --- | --- | --- |
| 1 | 选定持久化边界与数据表：Agent Run、Step、幂等记录、Memory；先说明用户/租户键和保留期限 | Repository 契约测试、跨租户拒绝 | DeepSeek 规划订单任务并写入持久化 Run |
| 2 | 将 Checkpoint/幂等状态放入 MySQL 或 Redis，模拟进程重启后恢复“已改订单、待通知” | 重启恢复、重复请求零额外副作用 | DeepSeek 触发任务，重启后继续并核对结果 |
| 3 | 将长期 Memory 持久化并加入 TTL/删除；避免不同租户共享对话 | 重启后同租户可读、异租户不可读、过期删除 | 两轮 DeepSeek 对话跨重启验证 |
| 4 | 将 RAG 接到 pgvector 或 Qdrant，检索前施加租户/文档权限过滤，并验证更新、删除和重建 | 无权限文档召回为零、删除后不可检索 | DeepSeek 对同题按不同租户给出不同授权引用 |

## 完成标准

- [ ] 服务重启后可安全继续 Agent Run；重复请求不会重复业务副作用。
- [ ] Memory 有用户/租户隔离、保留期、删除策略。
- [ ] 向量检索在模型看到片段之前就完成文档级授权过滤。
- [ ] 关键数据可备份、迁移与重建，测试使用容器或可复现环境。

持久化让任务能继续，下一步还要知道它为什么慢、为什么失败、花了多少钱，因此进入优先级 3。
