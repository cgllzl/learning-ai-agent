# 优先级 1：产品界面与企业项目主链路整合

> 状态：待开始。建议 8 个学习日；接 Day 6.1。对应现有 `Week-07-08-企业级项目`、Sprint 2/3/5/6/7/8/11。

## 先回顾，再说明为什么学

第一阶段分别完成 Chat、RAG、Tool、Workflow、权限和评估。下一步把这些能力做成用户能操作的企业工作台，并验证它们在同一次真实请求中按正确顺序配合。

本阶段虽然前端工作较多，学习顺序仍是“先定后端领域与 API 契约 → 再用前端呈现”。每一天的核心代码指南先解释 Java 主链路，前端只选与接口、流式状态、角色权限直接相关的代码精读。

## 八个学习日

| 日 | 学习任务与企业例子 | 离线验证 | 真实模型验证 |
| --- | --- | --- | --- |
| 1 | 完成产品定义、角色、页面地图、主链路与架构图；确定 React + TypeScript 前端和 Spring Boot 模块接口 | API 契约与路由测试 | DeepSeek 分别识别订单与知识请求 |
| 2 | 建立前端工程、登录页、角色/租户演示账号、响应式后台布局和统一错误状态 | 前端组件与权限路由测试 | 登录后调用真实 `/chat` 冒烟 |
| 3 | 完成 AI 工作台：SSE 流式对话、引用、执行步骤、停止/重试和失败提示 | 流式状态机、断线与重复提交测试 | DeepSeek 流式回答并显示引用/步骤 |
| 4 | 完成订单中心：分页筛选、订单详情、支付/物流时间线和售后入口 | 分页、跨租户与错误 Tool 用例 | DeepSeek 查询 O1001，UI 展示权威订单状态 |
| 5 | 完成知识库中心：文档列表、上传、权限、切片/索引状态、更新和删除入口 | 无权限文档不可见、引用可追溯 | DeepSeek 回答制度问题并在 UI 打开引用来源 |
| 6 | 完成审批中心：参数差异、批准/拒绝、过期、消费状态；串联取消/改状态流程 | 无审批零副作用、重复请求幂等 | DeepSeek 生成候选动作，界面显示待审批并阻止直接执行 |
| 7 | 完成 Trace、审计、Evaluation 和 MCP/Skill 治理页面的第一版 | 敏感字段脱敏、轨迹顺序和角色可见性测试 | 真实请求结束后可从 UI 查看调用链 |
| 8 | 使用 smoke 数据打通三条演示链，修复前后端契约，形成端到端冒烟命令和演示脚本 | 一条命令跑关键 UI/API 回归 | 知识问答、订单查询、高风险审批各完成一次真实演示 |

## 完成标准

- [ ] 用户能通过 Web 界面完成带引用知识问答、订单查询和高风险审批三条主链路。
- [ ] 登录、角色、租户、路由与危险按钮具有一致的权限表现。
- [ ] AI 工作台能显示流式回答、引用、Tool/Workflow 步骤和最终状态。
- [ ] 订单、知识库、审批、Trace、Evaluation、MCP/Skill 页面均有可操作第一版。
- [ ] 高风险请求无法跳过租户、权限、审批和审计。
- [ ] 失败请求有明确状态，不假装成功；Tool 与检索来源能在轨迹中看到。
- [ ] README 写清启动、最短演示路径、架构图和失败排查。
- [ ] 每天的笔记有通俗衔接、企业例子、首次新 API 说明和可运行 LiveTest。
- [ ] 每天另有“必看核心代码”Markdown，列出后端优先的阅读路线和1～3个重点测试。

通过这一步后，主链路已能跑，但服务一重启，内存状态可能丢失；因此进入优先级 2。
