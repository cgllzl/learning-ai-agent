# 优先级 1：企业项目主链路整合

> 状态：待开始。建议 5 个学习日；接 Day 6.1。对应现有 `Week-07-08-企业级项目`、Sprint 2/3/5/6/7/8。

## 先回顾，再说明为什么学

第一阶段分别完成 Chat、RAG、Tool、Workflow、权限和评估。下一步要验证这些模块在同一次真实请求中能按正确顺序配合，而不是只在各自的单元测试里成功。

## 五个学习日

| 日 | 学习任务与企业例子 | 离线验证 | 真实模型验证 |
| --- | --- | --- | --- |
| 1 | 画出现有入口和服务调用链；选“查 O1001 状态”和“根据 HR 文档回答”两条主场景，明确输入、输出与责任边界 | 主链路契约/路由测试 | DeepSeek 分别走订单与 RAG 分支 |
| 2 | 打通订单只读链：租户上下文 → 订单 Tool/MCP → 权威结果 → 带来源答复 | 跨租户与错误 Tool 用例 | DeepSeek 查询 O1001，核对真实 Tool 轨迹 |
| 3 | 打通企业知识链：文档权限过滤 → 检索 → 引用 → 回答 | 无权限文档不可出现、引用可追溯 | DeepSeek 回答内部制度问题并带真实引用 |
| 4 | 打通高风险请求：取消/改状态必须先校验、审批、执行、复核与审计；失败转人工 | 无审批零副作用、重复请求幂等 | DeepSeek 提出处理计划，受控链路拒绝未审批执行 |
| 5 | 建立演示入口和冒烟脚本；串联答案、业务结果和轨迹评估 | 一条命令跑端到端离线回归 | 两条业务链各一次真实 DeepSeek 演示 |

## 完成标准

- [ ] 用户能从一个入口完成至少两类请求：订单查询与带引用知识问答。
- [ ] 高风险请求无法跳过租户、权限、审批和审计。
- [ ] 失败请求有明确状态，不假装成功；Tool 与检索来源能在轨迹中看到。
- [ ] README 写清启动、最短演示路径、架构图和失败排查。
- [ ] 每天的笔记有通俗衔接、企业例子、首次新 API 说明和可运行 LiveTest。

通过这一步后，主链路已能跑，但服务一重启，内存状态可能丢失；因此进入优先级 2。
