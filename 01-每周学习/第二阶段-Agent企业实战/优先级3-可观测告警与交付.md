# 优先级 3：可观测、告警与交付

> 状态：待开始。建议 4 个学习日；依赖优先级 1～2。对应 Sprint 9/10。

## 为什么接着学

系统会运行、状态会保存以后，运维要回答“哪一步出了问题”。本阶段把现有项目内 Trace 和成本统计接到可查询的指标与告警，再整理成别人能启动和验收的交付物。

## 四个学习日

| 日 | 学习任务与企业例子 | 离线验证 | 真实模型验证 |
| --- | --- | --- | --- |
| 1 | 用 OpenTelemetry/Micrometer 贯通请求、模型、检索、Tool、审批的 traceId | Span 父子关系、敏感字段脱敏 | DeepSeek 订单查询，在 Trace 中找到完整链路 |
| 2 | 建立延迟 P95、错误率、Token/成本、循环次数指标和预算阈值 | 注入超时/失败，告警条件准确 | DeepSeek 正常与异常请求各一次，核对指标 |
| 3 | 完成 Docker Compose、配置分环境、健康检查和数据卷；从空环境启动 | 容器健康检查、重启后数据保留 | 容器中真实 DeepSeek 冒烟 |
| 4 | CI：构建 → 离线安全/评估 → 可选真实联调 → 部署测试环境；README 架构图、命令与回滚 | CI 故意注入失败时阻止交付 | 测试环境运行演示场景并记录结果 |

## 完成标准

- [ ] 一次请求的模型、检索、Tool、审批、错误与成本可在同一 Trace 关联。
- [ ] 错误、循环、成本超阈值能产生可验证的告警。
- [ ] 新机器按 README 可一键启动测试环境，关键数据重启后仍在。
- [ ] CI 能阻止安全/质量回归，项目资料可用于演示和简历。

系统可交付后，再引入真实第三方 MCP，缩小外部联调造成的排障范围。
