第一阶段像把发动机、刹车、导航分别装好并测试；第二阶段要造出一辆可以让别人坐进去操作、能看到仪表盘、能装载大量业务数据的完整车辆。项目必须有 Web 界面、真实业务形态的合成数据、完整企业流程和可核验的简历材料。产品范围与技术验收见 [项目产品定义与简历验收](项目产品定义与简历验收.md)。

## 每个学习日的固定验收

1. 先回顾上一天，再说明今天的知识为什么自然出现。
2. 一份学习例子、一份企业例子，附新语法首次注释与附近用法说明。
3. 一条无需 API Key 的自动化测试，以及一条真实 DeepSeek 的 LiveTest/联调命令。外部服务不可用时记录原因和可运行替代。
4. 当天知识库、学习日志、Sprint 状态同步；只有通过验证后才打勾。
5. 周期以验收结果为准，预计工作日仅供安排时间，不因为日期到了就宣称完成。

## 阶段结束标准

- 用户请求能走完对话 → 检索或 Tool → 权限/审批 → 审计 → 权威结果核验。
- React + TypeScript 界面覆盖 AI 工作台、订单、知识库、审批、审计、Evaluation 与系统治理。
- 数据生成器能稳定创建 smoke/demo/load 三档关联数据；load 档目标达到50万订单和100万审计事件。
- 服务重启后，执行状态与租户隔离仍正确。
- 一次请求可在 Trace 中定位模型、检索、Tool、延迟、Token 和失败原因。
- 测试环境一键启动，CI 能阻止明显回归，README 能让他人复现。
- 真实第三方 MCP 的边界完成后，再勾选远程集成项。
- 架构图、演示视频/脚本、截图、压测报告和简历描述全部来自真实运行结果。
