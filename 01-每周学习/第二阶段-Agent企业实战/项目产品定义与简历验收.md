# 第二阶段项目产品定义与简历验收

> 项目暂定名：Enterprise AI Knowledge & Operations Copilot
> 产品定位：面向企业客服与运营团队的多租户 AI 工作台，把知识问答、订单操作、人工审批、审计追踪和质量评估放在一个可操作界面中。

## 一、为什么它像企业项目

项目不是只有一个聊天框。不同岗位登录后看到自己的工作：客服查询订单和知识，主管处理高风险审批，知识管理员维护文档，审计员追踪谁在什么时间让哪个 Agent 调用了哪个 Tool，管理员查看模型成本、失败率和 MCP 状态。

主业务故事：

```text
客服收到客户问题
  → AI 判断是知识问题还是订单问题
  → RAG 或订单 Tool 取得受权限控制的事实
  → 高风险修改进入主管审批
  → 执行器携带幂等键操作业务系统
  → 再次查询权威状态
  → 用户看到结果，审计员看到完整 Trace
```

## 二、用户角色

| 角色 | 主要工作 | 关键权限边界 |
| --- | --- | --- |
| 客服专员 | AI 对话、查订单、查物流、查企业知识 | 只看所属租户；写操作只能发起申请 |
| 运营主管 | 处理取消、改状态等审批 | 审批绑定订单、动作、参数、有效期和次数 |
| 知识管理员 | 上传、更新、删除、重建企业文档索引 | 文档按租户、部门、访问级别隔离 |
| 审计员 | 查询 Agent 轨迹、Tool 调用和敏感操作 | 只读；敏感参数脱敏 |
| 系统管理员 | 管理用户、角色、模型、MCP 与预算 | 高权限操作全部审计，不接触明文密钥 |

## 三、必须完成的界面

| 页面 | 用户能做什么 | 简历展示点 |
| --- | --- | --- |
| 登录与演示身份 | 使用不同租户和角色的演示账号进入系统 | Spring Security、JWT、RBAC、租户上下文 |
| 运营总览 | 查看工单量、成功率、P95、Token、成本和待审批数 | 数据看板、成本与质量联合治理 |
| AI 工作台 | 流式聊天、查看引用、执行计划、Tool 步骤与最终状态 | LangChain4j、SSE、RAG、Tool Calling、Workflow |
| 订单中心 | 筛选订单、查看商品/支付/物流/历史、发起售后 | 大数据分页、领域模型、受控业务操作 |
| 审批中心 | 查看参数差异、批准/拒绝、检查过期和已消费审批 | Human-in-the-loop、参数级审批、幂等 |
| 知识库中心 | 上传文档、设置权限、查看切片/索引状态、更新与删除 | pgvector、租户过滤、索引生命周期 |
| Trace 与审计 | 按 traceId/用户/订单查询模型与 Tool 全链路 | OpenTelemetry、审计、脱敏、故障定位 |
| Evaluation 中心 | 查看用例集、成功率、P95、成本、失败原因和回归结果 | Agent Eval、Trajectory、Pareto、CI 门禁 |
| MCP / Skill 管理 | 查看已审核 Server、Tool 指纹、Skill 版本与状态 | MCP 安全准入、Skill 治理 |

界面采用 React + TypeScript + Vite，使用适合后台系统的组件库。布局要响应式、键盘可操作、状态清楚；每个危险按钮都显示影响对象和审批状态。

## 四、真实业务形态的合成数据

“真实数据”在本项目中指**结构、关联和分布接近企业业务的合成数据**，不使用真实客户隐私。数据生成器必须支持固定随机种子，同一个种子能重建同一批数据，方便测试和演示复现。

### 数据实体

- 租户、部门、用户、角色与权限；
- 客户、商品、订单、订单项、支付、物流轨迹；
- 售后工单、审批单、幂等记录、通知；
- 企业文档、版本、权限、切片和向量索引；
- Agent Run、Step、Memory、Tool 调用、审计事件；
- Evaluation 用例、执行结果、Token、成本和延迟指标。

### 三档数据规模

| 档位 | 用途 | 建议规模 |
| --- | --- | --- |
| smoke | CI 和快速启动 | 2 租户、50 用户、500 订单、50 文档、2,000 审计事件 |
| demo | 本地演示和截图 | 8 租户、2,000 用户、50,000 订单、2,000 文档、200,000 审计事件 |
| load | 分页、检索和告警压测 | 20 租户、20,000 用户、500,000 订单、10,000 文档、1,000,000 审计事件 |

数据不能只是随机字符串：订单金额遵循可解释分布，状态变化遵循状态机，物流时间晚于付款时间，退款不超过已付金额，审批必须关联真实订单和操作者，同时注入少量超时、取消、退款、权限拒绝等异常样本。

## 五、技术架构基线

```text
React + TypeScript Web
          ↓ REST / SSE
Spring Boot 模块化单体
  ├─ Identity / Tenant / RBAC
  ├─ Agent / Workflow / Skill
  ├─ Order / Approval / Audit
  ├─ Knowledge / RAG
  └─ Evaluation / Observability
          ↓
PostgreSQL + pgvector / Redis / MinIO
          ↓
DeepSeek / MCP Server / 外部业务服务
          ↓
OpenTelemetry Collector / Prometheus / Grafana / Trace 后端
```

第一版采用模块化单体，模块之间通过明确接口协作；等真实数据证明需要独立扩缩容时再拆服务。

## 六、简历级验收材料

项目完成时必须交付：

- 一张系统架构图、一张 Agent 调用链图、一张权限与审批图；
- 3～5 分钟演示脚本或视频，覆盖知识问答、订单查询、高风险审批和 Trace；
- 可点击的主要页面截图；
- Docker Compose 一键启动和 demo 数据生成命令；
- API 文档、数据模型、测试策略、故障恢复与安全边界；
- 真实测得的规模、成功率、P95、成本、恢复时间和压测结果；
- 一份中文项目介绍和一份简历项目描述。

简历只能写真实测得的数据。例如：

```text
基于 Java 21、Spring Boot、LangChain4j 构建多租户企业 AI 运营平台，
整合 RAG、Tool Calling、审批、MCP 与 Agent 轨迹评估；
在 ____ 条订单和 ____ 条审计事件的数据集上完成压测，
核心查询 P95 为 ____ ms，危险操作无审批调用率为 0%。
```

空白项必须由最终测试结果填写，不能提前编造。
