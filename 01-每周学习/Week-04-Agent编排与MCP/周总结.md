# Week 4 周总结：Agent Orchestration + MCP

- 日期范围：2026-08-23 ~ 2026-08-27
- 已完成：
  - Day 1：Agent Orchestration 模式（Supervisor / Handoff / Sequential / Parallel / Conditional / Agent State）+ 本项目编排图
  - Day 2：MCP 协议概念 + 跑通一个 MCP Server（官方 SDK stdio + add 工具）
  - Day 3：在 Java 项目里接入 MCP Client（LangChain4j `McpClient` + `McpToolProvider` 接线）
  - Day 4：把一个现有 Tool 改造成 MCP Tool（`OrderTools.getOrder` → `OrderMcpServer`），并打通真实 stdio + DeepSeek 联调
  - Day 5：Supervisor 模式（订单/知识两个子助手分派）
  - Day 6：多 Agent 状态传递与结果合并（订单 Agent → 客服回复 Agent）
- 遇到的问题 / 踩坑：
  - MCP stdio 的 stdout 被 Logback 日志污染，导致 `Ignoring message received because it is not valid JSON`（日志切到 stderr 解决）
  - MCP Server `main()` 里 `join()` 死等，导致客户端 `close()` 卡死（改成 main 正常返回、由非守护收包线程维持进程）
  - 最初 `McpOrderLiveTest` 只用了 `InMemoryMcpClient`，没有真正经过 Server；后改为 `DefaultMcpClient + StdioMcpTransport`
- 新学到的技术点：
  - MCP 核心概念：Client / Server / Tools / Resources / Prompts / JSON-RPC / 生命周期 / 授权
  - MCP Server 构建：`McpServer.sync(transport)` + JSON Schema 工具描述 + handler
  - MCP Client 接入：`StdioMcpTransport` + `DefaultMcpClient` + `McpToolProvider`
  - Supervisor：把子 Agent 包装成 `@Tool`，由 `@SystemMessage` 定义分诊规则
  - 多 Agent 状态传递：`@UserMessage` 方法级模板 + `@V` 参数注入，串行流水线合并结果
  - Java 语法：Builder 链式调用、`Map.of` / `List.of`、Lambda / 方法引用、`record`

  - Handoff / Parallel / Conditional 的代码级落地（本周只做了 Supervisor + Sequential 状态传递）
  - 接入第三方 MCP Server（本周主要接的是自己改造的 Server）
