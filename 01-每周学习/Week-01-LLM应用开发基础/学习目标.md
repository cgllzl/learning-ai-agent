# Week 1：LLM 应用开发基础

## 本阶段目标
建立 LLM 应用开发的最小认知闭环：LLM API → /chat 接口 → Streaming → Structured Output → 可靠调用。

## 必须掌握的知识
- LLM 是什么、Token、Context Window
- System / User / Assistant / Tool Message 四种角色
- Prompt、Temperature
- Streaming
- Structured Output（JSON Schema）
- Function Calling（了解即可，Week 2 深入）
- Model API、Token / Cost
- Retry / Timeout / Fallback

## Day 任务
| Day | 任务 | 产出 |
| --- | --- | --- |
| Day 1 ✅ | 搭建 JDK 17+、Spring Boot、Maven、Docker 环境，注册 LLM API Key | 能跑起空项目 |
| Day 2 ✅ | 调用 LLM API 完成第一个 `/chat`（JSON 输入 → 文本输出） | POST /chat 接口 |
| Day 3 ✅ | 加入 Streaming 流式输出（SSE） | /chat/stream |
| Day 4 ✅ | 加入 Structured Output：用 JSON Schema 约束输出格式 | 稳定的 JSON 响应 |
| Day 5 ✅ | 加入 Retry / Timeout / Fallback 与统一错误处理 | 健壮性测试通过 |
| Day 6 ✅ | 整理项目结构：service / controller / model 分层 | 代码分层清晰 |
| Day 7 ✅ | 写周总结，更新知识库与日志 | 周总结 + 知识库新增笔记 |

## 面试 / 工程问题
- Streaming 与普通请求的区别是什么？如何实现 SSE？
- Structured Output 为什么比「提示词要求 JSON」更可靠？
- 调用第三方 LLM API 时如何设计重试？指数退避怎么实现？
- Context Window 超了怎么办？（预告：RAG、Memory）
- 如何估算 Token / 成本？

## 完成标准
- [x] POST /chat 返回 JSON
- [x] /chat/stream 支持 SSE 流式输出
- [x] 输出被 JSON Schema 约束
- [x] 模拟 API 失败时能自动重试并优雅降级
