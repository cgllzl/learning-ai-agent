## 二、一次 /chat 请求的完整流程

```mermaid
flowchart LR
    A[Apifox / curl / IDEA HTTP Client] -->|POST /chat + JSON| B[Spring MVC<br/>DispatcherServlet]
    B --> C[ChatController]
    C -->|@Valid 参数校验| D[ChatService]
    D -->|组装 ChatMessage 列表| E[OpenAiChatModel<br/>LangChain4j]
    E -->|HTTPS POST /chat/completions<br/>Bearer Key| F[DeepSeek API]
    F -->|生成回复| E
    E -->|ChatResponse| D
    D -->|reply 文本| C
    C -->|JSON {"reply": "..."}| A
```

**逐步说明：**

1. **客户端发请求**：Apifox 发送 `POST http://localhost:8080/chat`，Body 为 JSON（`systemPrompt` + `messages`）。
2. **Spring MVC 路由**：`DispatcherServlet` 根据 `@RequestMapping("/chat")` 找到 `ChatController`。
3. **参数校验**：`@Valid` 触发 Jakarta Validation，检查 messages 非空、role/content 非空；不合法直接 400，不再调用模型（省钱省时间）。
4. **消息转换**：`ChatService` 把 DTO 的 role 映射成 LangChain4j 消息对象：
   - `system` → `SystemMessage`（设定角色）
   - `user` → `UserMessage`（用户输入）
   - `assistant` → `AiMessage`（历史回复）
   - 其他 role → `IllegalArgumentException` → 400
5. **调用模型**：`chatModel.chat(chatMessages)` —— LangChain4j 把消息列表序列化成 OpenAI 兼容请求，发给 `https://api.deepseek.com/chat/completions`，请求头带 `Authorization: Bearer <API Key>`。
6. **DeepSeek 生成**：模型按上下文生成回复，返回标准 JSON。
7. **反序列化**：LangChain4j 把响应解析成 `ChatResponse`，`ChatService` 取 `aiMessage().text()`。
8. **返回客户端**：`ChatController` 包成 `{"reply":"..."}`，Spring 用 Jackson 序列化回 JSON。

## 三、关键技术点原理

### 1. 为什么用 LangChain4j
- 它是 Java 生态的 LLM 集成框架，封装了「HTTP 调用 + JSON 序列化 + 消息模型 + 重试」等脏活。
- 我们只需要配置 baseUrl / apiKey / model，然后调用 `chat()`，后续加 Tools、RAG、Memory 都能在同一个框架内扩展。

### 2. OpenAI 兼容协议的意义
- DeepSeek 提供与 OpenAI 相同的 `/chat/completions` 协议，所以 LangChain4j 的 open-ai 模块开箱即用。
- 换模型只需改配置（base-url + model），代码不用动——这也是「标准化协议」的价值。

### 3. 消息角色的语义
- 消息列表 = 完整的对话上下文，按顺序传给模型。
- `system` 优先级最高，用于约束模型角色和行为；`user`/`assistant` 交替构成多轮对话。

### 4. 密钥为什么走环境变量
- Key 写死在代码/配置文件里会被提交到 git，泄露风险大。
- `application.yml` 用 `${DEEPSEEK_API_KEY:}` 占位，启动时从环境变量注入；`.env` 被 `.gitignore` 排除，`run-dev.ps1` 负责把 `.env` 桥接成进程环境变量（Spring Boot 不直接读 `.env`）。

### 5. 校验与错误处理的设计
- 入参校验前置（400），AI 调用失败兜底（502），统一由 `ChatExceptionHandler` 处理。
- 好处：客户端拿到明确的错误信息，日志里不堆裸异常。

### 6. LangChain4j 1.x 与 0.x 的差异（易踩坑）
- 1.x：`ChatModel.chat(List<ChatMessage>)` 返回 `ChatResponse`，取 `aiMessage().text()`。
- 0.x：`ChatLanguageModel.generate(...)` 已移除，旧教程代码会编译报错。

### 7. 测试策略
- **单元测试**：Mock 掉 `OpenAiChatModel`，不花钱、不依赖网络，测消息转换和逻辑。
- **控制器测试**：`@WebMvcTest` + MockMvc，测路由、校验、错误码。
- **真实联调**：Apifox / curl 打真实 DeepSeek，验证端到端可用。
